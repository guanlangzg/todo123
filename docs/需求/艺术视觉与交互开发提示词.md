# 艺术视觉与交互开发提示词

> 用途：交给负责 Android 界面、视觉资源与验收的设计师或 AI 开发代理，**作为独立可执行的创作简报**。实际产品需求及状态/数据规则以 [Android 个人艺术 Todo 开发需求规格](Android个人艺术Todo开发需求规格.md) 为准；真实用户选项见 [访谈档案](需求访谈与决策记录.md)。当前没有高保真设计稿、艺术素材、APK 或实测截图。
>
> 标记：**[用户已确认]** 表示已有真实选择；**[设计默认]** 表示为实现落地提出的视觉方案，可在完整视觉稿审阅时基于证据调整，不能当作用户逐项选择。

## 可直接交给设计/开发代理的任务

你正在为一个人长期使用的 Android 手机应用设计并实现一套有原创识别度的原生艺术界面：清晨打开即可看清今天要做什么，点任务卡片选择正向计时或自定义分钟倒计时，投入完成后通过日历和丰富但准确的统计获得反馈。**高级艺术美学和流畅交互是第一版的首要验收要求。[用户已确认]** 不得先交白底通用任务列表、默认图标和占位插图，再承诺“后面加皮肤”。

设计与交互必须由 **Kotlin + Jetpack Compose 原生 UI** 承载；Rust 经 UniFFI 承担任务、计时、跨日与统计的领域规则，Kotlin 管 Room、Android 生命周期、通知与文件。不能以 WebView、静态图片模拟可操作页面，也不能为了视觉效果让 UI 和 Rust 各自计算一套计时/统计。[用户已确认：Q51]

只有 Android 手机首发、离线可用、无账号；APK 为首发分发目标，开发注意未来商店规范，无 Google Play 上传或注册目标。首版提供精心搭配、取得打包展示权的内置艺术视觉。**后期**才加入内置精选图的手动替换、用户本地上传、离线随机；任何图分配给任务后保持稳定，用户主动更换才改变。[用户已确认]

你应交付的成果：可审阅的原创设计方向说明、设计 tokens、至少覆盖下列关键页面及状态的高保真方案与 Compose 原生实现、资源授权清单、截图回归基线、TalkBack 与真机互动/性能评审记录。实现工作开始前，应先有可审阅视觉稿与授权素材；本文件本身并不授权现在搭建应用。

## 产品叙事与艺术方向

[设计默认] 主张“**私人的工作室日历**”：应用像一本当代艺术家工作手册，有展签式日期、编辑式文字编排和经过编辑的鲜明插画；背景与容器宁静，重点作品和行动按钮有鲜明色彩。视觉表达投入与持续行动，避免游戏化打卡羞辱、虚构效率奖励、满屏烟花、廉价拟物、磨砂玻璃叠满、全页面无差别渐变和大面积低对比度灰字。追求有温度的精致，不是照搬某一款产品的像素或第三方插画。

- **绘画语言 [设计默认]**：以少量自有的现代编辑插画作为首版艺术系统：有限调色、明确轮廓、自然物/纸片几何叠层、轻纸纹或丝网印刷颗粒，局部可带柔和空间光。每幅提供留白区和裁切安全区，人物/物件/色块不会与标题竞争。优先可组合的原创系列而不是无主题的网络图片包；色彩鲜亮但 UI 留白足够。
- **页面气质 [设计默认]**：首页有一处面积可控的“今日封面”，展示日期、当天行动的情绪锚点，随后立即出现未完成临时任务和日常任务；首屏不能被大幅装饰遮蔽任务与开始按钮。插画只在首页封面、任务卡、专注背景的局部、无数据空态和统计标题等有限位置使用，不给每个单元同等视觉权重。
- **原创与授权 [硬要求]**：逐个资源记录作者、来源 URL、许可证/购买协议版本、允许的商用/修改/再分发范围、署名要求、归档证明及尺寸/色域；仓库和 APK 内的资源与清单对应。生成素材也需保留生成过程、参考来源及商用条款核验。不要默认博物馆 API 返回的作品均可重新打包，也不要复制 Things 3、Sunsama、Structured、Endel 的商标、插画或页面。公开参考资料只证明它们可被研究，不代表视觉实测已完成。

### 起始设计 tokens（仅为设计默认提案）

| 类别 | 初始提案与意图 | 最终确认方法 |
| --- | --- | --- |
| 基底 | 奶油纸 `#F5F0E8`；卡片浅白 `#FFFFFF`；主墨色 `#192C3B` | 检查真机光照、暗色模式及截图库；卡片边界可见但不过度投影 |
| 信息色 | 次级墨色 `#596771`；高注意赭红 `#B64931`；插画辅色可用蓝绿/钴蓝/柠黄 | 每个“文字对具体底色”的组合逐项测量；不可只对主背景检查 |
| 文字 | 中文正文采用系统可缩放字体或明确授权的 CJK 字体；数字计时可用独立可读的等宽数字；大标题可用编辑式中西文字重差 | 查实际字体授权、中文形状、字重、字距及字体缩放；不依赖远程字体下载 |
| 尺寸节奏 | 8 dp 基础节奏，卡片内边距约 16–20 dp、组间约 24–32 dp；核心触控目标至少 48×48 dp | 在小屏、字体放大、手势导航/状态栏避让下检查；不是所有屏幕机械套固定值 |
| 形状/层级 | 少量不同圆角与细边界；首屏只给当前进行中的计时最高互动权重，艺术图作为第二焦点 | 清晰的未完成/完成/归档状态，不靠投影强弱或颜色独立表达 |
| 主题 | 首版以完整浅色艺术主题为主；如提供深色主题，同样设计全部状态和插画遮罩，不能直接颜色反转 | 为每个主题分别做对比度与整页评审；系统深色偏好要么完整支持，要么避免破碎主题 |

上述主文字与浅纸底对比度约 **12.64:1**、次级文字约 **5.14:1**、赭红文字约 **4.64:1**（基于 sRGB WCAG 算法的静态计算）；这不是插画叠底、透明层或真机最终页面的验收结果。赭红在渐变、半透明与插画表面不得直接当正文色。通常大小正文至少 4.5:1，大字至少 3:1；图表与状态图标也需可读且不只依赖颜色。

## 需要逐屏设计的体验

| 页面/状态 | 首要信息与层级 | 必要交互和视觉约束 |
| --- | --- | --- |
| 今天首页，空/有任务 | 日期与固定应用时区提示可从设置查到；**临时未完成始终排在日常前**；日常未完成、已完成折叠区、显眼的新建入口 | 日期跨 00:00 更新任务状态不重置正在运行的计时；完成、打开任务、长按拖动及无障碍排序是不同动作。空态有原创艺术，但首个任务创建按钮仍明显 |
| 临时任务组 | 保留到用户完成或归档；组内手动顺序稳定 | 完成后的任务从首页进入历史；历史可重新打开续做。名称、备注过长时保留可读标题与动作 |
| 日常任务组 | 每天都有新的完成状态，历史独立，昨天漏做不堆到今天 | 已完成折叠区展开/收起与撤销明确；归档后的历史仍能查，重新启用当天出现。避免把“昨天未完成”做成惩罚性角标 |
| 任务详情与计时选取 | 标题、备注、正向/倒计时两个清楚的模式，倒计时输入上次该任务的分钟或新任务 25 分钟 | **选择模式不启动计时，必须点“开始”**。输入有可见标签与错误提示；不让图像抢占主要操作 |
| 正向/倒计时专注 | 当前任务与可读的大计时数字、运行/暂停、结束；唯一活动会话 | 视觉安静、边界清晰；暂停时数字不继续累计；切任务和主动完成先确认保存当前投入；倒计时到点停止，结果页明确选“休息”或“继续专注”，前者不启动休息计时，后者还需按“开始”新段，不自动勾选 |
| 跨日与异常恢复 | 跨午夜继续；主动完成时选择相关日期、默认突出今天；异常段待确认 | 提示已确认时长与推算空档，提供接受/修正/舍弃三个动作；数据风险文案优先于艺术装饰，绝不把未确认区间展示为已投入 |
| 历史/日历 | 日期概览、每日总量、任务投入、每条明细来源与完成状态 | 日期为空、修正为零、跨日自动拆分、日常归档期间空白都需明确表达；当前名称不覆盖旧历史快照 |
| 统计/热力图 | 周/月趋势、任务占比、逐日热力图；悬空提示或点击详情带精确值 | GitHub 风格方格但需要可读图例、零值与无记录区分、日期语义和辅助列表；不能按每段取整后相加。长标题不截断到不可辨识 |
| 手动时长编辑 | 新增实际投入或将某任务某日总量修正为具体值，两种模式的前后总量预览 | 别伪造开始/结束时间；保留原计时，显示“本次修正”和来源，防止把想填的总量又累加一次 |
| 设置/备份 | 到点震动默认、可开声音；固定应用时区及手动变更入口；手动导出、七日滚动本机恢复点和完整替换式恢复 | 手动改应用时区前展示旧/新日期和刷新影响，历史不重排；备份可选密码保护；恢复前显示替换警示、失败不改变旧数据；本机恢复点不能暗示防丢机或防卸载 |

**导航 [设计默认]**：底部最多四个主要目标（今天、记录、洞察、设置），进行中的专注在首页有持续状态卡，可回到专注页；不单设永久第五个计时入口。Android 系统返回、返回手势、键盘关闭、转屏和进程重建均回到可预期的状态，不重复启动计时。图像加载失败时文案和控制不移动到不可达位置。

**失败与极端状态**：图源缺失、零统计、长任务名、超长备注、大字号、折叠区数十项、错误密码、通知权限拒绝、备份存储空间不足、时钟异常、进程重建，都要画出界面与可恢复动作。只做漂亮的正常态截图不能通过评审。

**记录日期与时区 [设计默认]**：时间账本按事件发生瞬间有效的应用时区归日；用户主动切换应用时区只影响之后的记录，不重算旧历史。过去计时明细和临时任务完成事件按当时的标题版本呈现，归档与完成各有独立状态，不用一张“已结束”图标混淆两者。

## 微交互与性能

- [设计默认] 卡片点开/收起、完成与撤销、计时开始/暂停、热力格子选中、归档与恢复采用少量保持空间关系的动效。动作后先给可见反馈，再进行非关键动画；状态最终以真实持久化结果为准。可参考 150–250 ms 的快速状态过渡作为起始值，具体由真机感知测试修正；不能拿一套时长套所有页面。
- 图片在 Compose 中按展示尺寸预解码/缓存，避免整幅原图进入列表；占位尺寸固定，文字与完成控制不因加载跳动。每秒更新的数字只影响计时区域，不强制整页与统计重组。懒加载的长列表与热力图在真实中端机上滚动测试，不能用模拟器截帧代替。
- 系统减少动画/动效偏好须提供等价的状态改变反馈；TalkBack 正朗读时避免自动动画抢焦点。震动只用于到点与必要反馈，不把普通页面装饰做成连续触觉噪声。Android 前台持续通知与到点提醒遵循系统权限与限制，不设计绕开系统的“保证响铃”。
- 与 [开发需求规格](Android个人艺术Todo开发需求规格.md) 中真实中端设备的冷启动、帧、内存/耗电目标一致；所有数字是待测目标，未开始开发时不得写“已达到”。

## 无障碍和尊重用户

- Compose semantics 为每项任务、完成状态、计时状态、剩余时间、统计日期与格子提供可读的名称、角色与动作；长标题需有完整 TalkBack 读法。任务卡与独立完成控件避免重复或互相遮挡的语义节点；确认弹窗焦点进入、退出后返回原焦点。
- 手动拖动排序必须有菜单中的“上移/下移”等可单指触发的替代动作；热力图给带日期和分钟的列表/语义索引；图表提供表格化明细，不让色盲或 TalkBack 用户只能读一片颜色。
- 所有主要操作目标至少 48 dp；相邻误触区留足间距。支持 Android 系统大字号、显示大小、深色模式策略、状态栏/导航栏 inset；不把关键信息画到摄像头开孔、边缘手势区或键盘下。
- 不使用让人焦虑的红色“拖延惩罚”、欺骗式连续打卡或未经确认的“你有 X 小时有效学习”文案。归档不代表完成，计时投入不代表该日完成；色彩和文案必须遵守产品语义。

## 视觉审查与出图标准

1. **先看整组页面**：至少交付今天首页（有任务/空态）、临时与日常卡片、任务详情及模式选择、运行/暂停/到点、跨日完成、异常恢复、历史日历、热力图/趋势/占比、手动修正、设置/备份及错误提示的实际尺寸高保真状态。单屏海报不代表应用体验。
2. **再审查资源**：每幅艺术图记录权利证据、尺寸、色域、裁切安全区、缩略图与失效时替代视觉；按不同长短标题和文字叠加位置验证。禁止把无许可高清大图直接打进 APK。
3. **完成原生实现后出回归材料**：同一测试数据集，在至少一台真实中端 Android 设备上录制从首页到开始/暂停/完成/记录的交互，采集关键页截图；测试小屏、大字体、光照环境、黑白/色弱模拟、TalkBack 和系统减少动画。截图回归能找视觉漂移，但不代替人体操作检查。
4. **验收标准**：用户在首页无需阅读说明即可区分临时与日常、找到下一件事，并清楚走完“打开卡片 → 选模式/确认倒计时分钟 → 点击开始”，在最后一步之前绝不计时；运行和暂停不会混淆；统计任一颜色格子都能查到日期/精确时长；任一任务卡图片丢失后仍可读可操作；动画不妨碍点击，真实设备测量满足规格中明确的性能目标或提供偏差证据与修订说明。艺术方向须由整组页面的连贯性而非某张宣传图体现。

**交付声明**：目前交付的是完整开发提示词和审查准则；具体艺术画稿、字体授权、UI 原生实现、截图回归、TalkBack 与真机性能结果，必须在后续实际开发时分别完成并留下证据，不能把设计默认当作用户明确选色，不能把计划中的验证描述为已完成。
