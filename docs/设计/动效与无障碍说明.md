## 1. 动效设计原则

| # | 原则 | 判据 |
| --- | --- | --- |
| M1 | **先反馈，后动画** | 每个状态变化在动画开始前已有非动画可见变化（颜色/文字/图标立即翻转）。动画只是补足空间关系，不是状态的唯一载体 |
| M2 | **空间连续性** | 元素从 A 位置移动到 B 位置时，用同一个 composable 连续移动，不做「消失 + 出现」两段 |
| M3 | **同屏动画 ≤2 个** | 一个动作最多让两个元素同时运动；高频列表整体不做入场动画 |
| M4 | **动画期间点击不丢** | 命中区取动画起止位置的并集，或动画期间锁定但明确禁用态 |
| M5 | **每秒重绘有严格边界** | 计时 tick 只重绘计时数字 `Text` 与剩余时间，不触发列表重排、不重算统计 |
| M6 | **能小不大** | 时长取满足可感知性的最小值；不用"更长的动画"表达更高级 |
| M7 | **减少动画下有等价物** | 关闭动画后，每个状态变化仍有 ≥2 条非动效通道（颜色 + 文字/图标） |

## 2. 四个重点动效

### 2.1 任务完成

触发：点任务卡右侧完成控件（独立 48dp 命中区）。

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| t=0 | 0ms | 完成控件立即从空心圆 → 实心勾（**非动画的即时变化**，满足 M1）；卡片标题立即转 `inkSecondary` |
| t=0–120ms | 120ms | 勾选涟漪/缩放 0.92→1.0，`LinearOutSlowInEasing`；触觉：轻微 `HapticFeedbackType.LongPress`（**仅此一次**，与到点振动区分） |
| t=80–320ms | 240ms | 卡片从原位置移动到已完成区，`FastOutSlowInEasing`；用 `Animatable` 的偏移 + `Modifier.animateItem`，保持空间连续（M2） |
| t≥320ms | — | Snackbar 出现「已完成『微信读书』」+「撤销」，8 秒 |

**只动 1 个元素**（该卡片），列表其余项目不做同步位移动画，改为即时跳位——避免长列表整体运动（M3）。

减少动画下的等价反馈：勾选立即变实心、标题立即变色、卡片**立即**出现在折叠区（无位移）、Snackbar 正常出现。**无位移但状态完全可辨**。

TalkBack 侧：动画开始前先发 `liveRegion = Polite` 的「已完成，微信读书」；撤销可用时，Snackbar 的「撤销」是独立可聚焦节点。

### 2.2 卡片展开（折叠区展开/收起 + 任务详情展开备注）

触发 A：点「已完成 N 项」折叠标题带。
触发 B：点任务卡展开备注（可选，见关键页面说明 §0.3）。

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| 0ms | — | 折叠标题带右侧 `ic_expand` 立即旋转 180°（`rotationZ`，无过渡起点，靠图形朝向变化本身给反馈）；标题带文字由「已完成 3 项」→「收起已完成 3 项」 |
| 0–240ms | 240ms | 内容高度 0 → 目标高度，`FastOutSlowInEasing`，用 `animateContentSize()`；`clipToBounds()` 防止内容溢出 |
| 展开完成后 | — | `Modifier.focusRequester` 不抢焦点；若用户从无障碍焦点进入，焦点保持在被点击的标题带上 |

- **不使用** `AnimatedVisibility` 的淡入淡出叠在高度变化上（两层同时运动会违反 M3）。
- 列表内部为独立 `LazyColumn`（关键页面说明 §1.3「折叠区数十项」），最大高度 60% 视口，超出自身滚动；展开动画只作用于容器高度上限，不预渲染全部子项。
- 收起后 Snackbar「已收起」。

减少动画下的等价反馈：内容**立即**显示/隐藏；`ic_expand` 图标改为 `ic_collapse` 的另一图形（不靠旋转）；标题文字同步变化。

### 2.3 计时启动 / 暂停

触发：专注页「开始」「暂停」「继续」；今天页状态卡的出现与消失。

**启动**（`Running`）：

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| 0ms | — | 按钮文字立即由「开始」→「暂停」，按钮底由 `accent` 实心 → `running` 描边；**这是状态确认的主通道** |
| 0–180ms | 180ms | 计时数字由 `--:--` 淡入至 `00:00:01`（alpha 0→1），`FastOutSlowInEasing` |
| 0–1200ms | 1200ms 循环 | 数字左侧 8dp 呼吸点：alpha 0.35↔1.0，`EaseInOut`。**全应用唯一的循环动画** |
| 首页侧 | ≤300ms | 状态卡从顶部 8dp 位置滑入（偏移 8dp + alpha），`FastOutSlowInEasing`；任务卡左缘 4dp `running` 竖条即时出现 |

**暂停**（`Paused`）：

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| 0ms | — | 按钮文字立即「继续」；计时数字色立即转 `inkTertiary`；标签立即改「已暂停」；呼吸点**立即**变静态实心点 |
| 0–180ms | 180ms | 呼吸点的 alpha 动画取消（`Animatable.snapTo`），数字**不**做任何过渡——暂停的确切数值必须稳定可读 |
| 0–180ms | 180ms | 首页状态卡左缘竖条由实线 → 虚线（线段偏移动画） |

**关键约束**：
- 暂停后计时数字**停止更新**（规格 §5.1「暂停时数字不继续累计」）；若动画仍在跑却数字不动，会被读作"卡了"，因此暂停时数字不做模糊/缩放类动画。
- 恢复后从 `Paused` 的分秒继续，间隔无累积跳变。
- 启动/暂停都**不**改变页面其他元素位置（M5），避免中断阅读。

减少动画下的等价反馈：呼吸点改为静态实心点（红色/青绿 + 文字「进行中」）；状态卡立即出现（无滑入）；数字立即显示。**暂停态与运行态的区分仍由「数字颜色 + 标签文字 + 竖条实/虚 + 按钮文案」四重承担**，与动画无关。

TalkBack：计时状态变化通过 `LiveRegion.Polite` 播报一次「计时已开始」「计时已暂停」，**不做**每秒播报（规格要求「TalkBack 正朗读时避免自动动画抢焦点」，每秒播报会把朗读彻底淹没）。

### 2.4 热力图选中

触发：点按/拖动热力图区域，选中最近格。

| 阶段 | 时间 | 内容 |
| --- | --- | --- |
| 0ms | — | 下方详情卡**立即**更新日期与精确值（这是主反馈，M1） |
| 0–180ms | 180ms | 选中格由 6.5dp 放大到 8.5dp，同时 1dp `accent` 描边 alpha 0→1；`FastOutSlowInEasing` |
| 0–180ms | 180ms | 若上一格仍有描边，其描边先淡出（不叠加两个描边） |
| 定位 | — | 选中格若在可视区外，横向滚动 `ScrollState.animateScrollTo` 到居中，180ms |

- 缩放范围**严格限制在 6.5→8.5dp**（+31%），使相邻格视觉重心位移 ≤2dp，不会让用户误判自己点的是哪一格。
- 不缩放热力图容器整体（53 周网格放大整块会产生巨大位移）。
- 拖动选择（连续跟手）时不加动画，只用 `snapTo` 跟随手指，松手后 180ms 收敛（`motion.stretch` 弹簧）。

减少动画下的等价反馈：**不放大**，改为 2dp `accent` 描边（比 1dp 更粗，纯静态差异）；详情卡立即更新。此时选中态的区分由「描边粗细 0→2dp + 详情卡内容 + TalkBack 播报」承担。

TalkBack：每次选中变化播报一次「2026 年 3 月 4 日，投入 1 小时 32 分钟」（`LiveRegion.Polite`，**节流至 ≥600ms 一次**，避免拖动时连续播报刷屏）。

## 3. 其余动效清单

| 场景 | 时长/曲线 | 说明 |
| --- | --- | --- |
| 按压反馈（所有可点元素） | 120ms `LinearOutSlowInEasing` | 缩放 1.0→0.98 + `accentTint`/`surfaceTint` 叠层；仅手指按下期间 |
| 页面转场（底部导航切换） | 300ms，入 `FastOutLinearInEasing` / 出 `LinearOutSlowInEasing` | 同一 tab 重复点击**不**重复转场，而是回到列表顶部 |
| 模式选择卡片选中 | 180ms | 描边 `lineHairline`→`accent` 2dp + 底色→`accentTint`；同屏只允许一张卡处于选中态 |
| 撤销（Snackbar 出现/消失） | 240ms `motion.stretch` 弹簧 | 从底部 16dp 处弹入；消失用 180ms 淡出 |
| FAB 因 Snackbar 上移 | 180ms `FastOutSlowInEasing` | 上移距离 = Snackbar 高度 + 8dp（关键页面说明 §0.2） |
| 归档 / 恢复 | 240ms | 卡片淡出（alpha 1→0，同时高度收缩）；**不**做飞入文件夹式的意象动画 |
| 跨日日期选项出现 | 240ms `FastOutSlowInEasing` | 两个日期大按钮从下方 12dp 滑入；`accent` 强调默认"今天"的描边在 300ms 后开始一次 1 次性脉冲（不循环），提示默认选项 |
| 到点提醒（应用内结果页） | 360ms | 数字从 52sp 缩放 0.94→1.0；**不**做烟花/彩带/满屏粒子（原则 P6、视觉提示词禁止项） |
| 时区变更确认全屏 | 无动画 | 数据风险语境，直接显示（减少动画优先于视觉仪式感） |
| 备份替换警示 → 恢复进度 → 结果 | 进度用 600ms 循环的**线性**不确定进度条 | 唯一允许的第二处循环动画，仅在真实等待期出现 |

**明确不做**：列表项入场动画（首屏 100ms 内必须可读）、页面间共享元素转场（跨页面共享 72dp 缩略图会引入测量抖动）、数字滚动/翻牌效果（会掩盖精确值）、任何庆祝类全屏动画。

## 4. 系统「减少动画」偏好

### 4.1 判定

Compose 中读取 `LocalAccessibilityManager` 的 `isEnabled` 不足；需读取系统动画缩放：

- `Settings.Global.ANIMATOR_DURATION_SCALE == 0`
- `Settings.Global.TRANSITION_ANIMATION_SCALE == 0`
- `Settings.Global.WINDOW_ANIMATION_SCALE == 0`

任一为 0 视为「减少动画」。通过 `StudioTheme` 注入 `LocalReducedMotion`，供全应用读取（**不使用** Material3 的 `MotionScheme` 承载该判断——见设计系统 §10.1：本工程锁 material3 1.4.0，无法核实其 `motionScheme` API，且该判断不应依赖它）。

替代方案（若上述读取在目标设备上不可靠）：Compose 侧可读 `LocalMotionDurationScale`（`androidx.compose.ui` 提供），其 `scaleFactor` 为 0 时同样视为「减少动画」。两条路径应在阶段 C 各测一次，取在真机上确实随「移除动画」开关变化的那一条。**本项未在设备上验证**。

> 原型侧对应物：`docs/设计/视觉原型.html` 的「减少动画」开关，以及默认读取 `prefers-reduced-motion`。
> `scripts/test/verify_prototype_offline.py` 断言该开关生效（禁用 CSS 动画/过渡）。这只是浏览器侧的接线验证。

### 4.2 逐场景等价反馈对照表（验收用）

| 场景 | 有动画时 | 减少动画时的等价反馈（**必须全部保留**） |
| --- | --- | --- |
| 任务完成 | 勾选缩放 + 卡片位移入折叠区 | 空心圆→实心勾（即时）+ 标题转 `inkSecondary` + 卡片即时出现在折叠区 + Snackbar「已完成 ××」+「撤销」 |
| 折叠区展开 | 高度 240ms + 图标旋转 | 内容即时显示 + 图标换图形（`ic_expand`→`ic_collapse`）+ 标题文字「收起已完成 N 项」 |
| 计时启动 | 数字淡入 + 呼吸点循环 + 状态卡滑入 | 数字即时显示 + 静态实心点 + 标签「进行中」+ 状态卡即时出现 + LiveRegion 播报 |
| 计时暂停 | 呼吸点停 + 竖条实→虚 | 数字转 `inkTertiary`（即时）+ 静态点 + 标签「已暂停」+ 竖条改虚线（即时换图形，无过渡） |
| 热力图选中 | 格放大 + 描边淡入 + 滚动居中 | 描边直接 2dp（无淡入）+ 详情卡即时更新 + 滚动静默跳转（`scrollTo` 而非 `animateScrollTo`）+ 播报 |
| 撤销 | Snackbar 弹簧弹入 | Snackbar 即时出现（无位移），倒计时 8 秒不变 |
| 归档/恢复 | 淡出 + 高度收缩 | 即时消失/出现 + Snackbar 确认 |
| 页面转场 | 300ms 滑动 | 即时切换（无转场） |
| 到点结果页 | 数字缩放入场 | 即时显示 + 震动（震动是触觉反馈，不受动画偏好影响） |

**验收判据**：把三个动画缩放都设为 0 后逐项走查上表右列，每一项都必须能凭右列通道**唯一确定**状态，不得出现"看起来和另一个状态一样"。

### 4.3 减少动画下仍保留的动效

- **按压反馈**（120ms 缩放 + 叠层）：保留。它提供点击确认，且幅度极小（0.98），不引发前庭反应。
- **不确定进度条**（备份/恢复）：保留为线性循环。它表达"仍在工作"，取消会让长等待看起来像卡死。若用户同时开启省电模式，改为每 800ms 切换一次的静态文本「正在恢复…／仍在恢复…」。
- **纸纹材质**：保留（静态纹理，与动画无关）。

### 4.4 与省电模式叠加

`PowerManager.isPowerSaveMode` 为真时：
- 关闭纸纹（一次全屏纹理合成）。
- 关闭呼吸点与不确定进度条动画。
- 热力图选中不加放大。
- 计时数字由「每秒」改为「每 5 秒」重绘（**仅影响重绘频率，不影响已记录秒数**；用户离开专注页时以真实秒数结算）。

## 5. 拖动排序的单指 / 读屏替代操作

### 5.1 合规依据

WCAG 2.2 **SC 2.5.7 Dragging Movements**（AA）：所有使用拖动操作的功能必须能用单指（不拖动）完成。本应用中被拖动影响的只有**同组任务的顺序**。

### 5.2 三条等价路径（全部必须实现）

**路径 1：卡片菜单「上移 / 下移」**

```
任务卡 → ic_more（48×48dp）→ 弹出菜单
  ├ 上移                    ← 一级项，48dp 行高
  ├ 下移                    ← 一级项，48dp 行高
  ├ 移到组首
  ├ 移到组末
  ├ 编辑标题与备注
  └ 归档
```

- 首项与末项到达组边界时，对应项置灰并给 `contentDescription`「已在组首」。
- 操作后 Snackbar「『微信读书』已上移」+「撤销」8 秒。

**路径 2：TalkBack 自定义无障碍操作（自定义 Actions）**

任务卡语义节点上挂 `CustomAccessibilityAction`：

| 动作标签 | 作用 |
| --- | --- |
| 上移 | 同路径 1 |
| 下移 | 同路径 1 |
| 移到组首 | 同路径 1 |
| 移到组末 | 同路径 1 |
| 开始计时 | 直接进入模式选择 |
| 切换完成状态 | 完成 / 撤销 |
| 归档 | 归档（保二次确认） |

TalkBack 用户通过「向上/向下滑动切换操作」后双击执行，**完全不需要拖动**。

**路径 3：长按进入排序模式中的「上移/下移」按钮**

长按卡片进入排序模式后，每张卡片左缘出现「上移 ⌃」「下移 ⌄」两个 48dp 按钮（视觉 32dp），可单指逐格点击。这是给"看见了拖动、但手部控制不便"的用户。

### 5.3 拖动自身的要求

- 长按 400ms（`ViewConfiguration.getLongPressTimeout()`）进入排序；**不**用短滑手势（与列表滚动冲突）。
- 拖动期间卡片放大 1.03、`elevation` 提升、出现半透明占位槽（表示将被插入的位置）。
- 拖动跟手用 `motion.stretch` 弹簧；**不与滚动动画同时进行**（拖动期间锁定列表滚动方向）。
- 松手后落位 180ms；同组顺序立即写入持久层。
- 排序只在**同组内**进行：临时任务与日常任务是两个独立组，跨组拖动被拒绝并给 Snackbar「临时任务与日常任务不能混排」（规格 §4.1/§4.2 两组各自的顺序独立）。
- 拖到列表边缘（上下 48dp 区域）触发自动滚动，速度上限 600dp/s。

### 5.4 顺序的持久化语义

拖动的结果必须与「新日不重置」一致（规格 §4.1「手动拖动调整日常区顺序，重启和新日沿用」）。放弃拖动（松手在组外或按返回）不写入任何变更；已完成的排序不产生"顺序历史"概念，只有当前顺序。

## 6. TalkBack 语义与阅读顺序

### 6.1 全局规则

| 规则 | 实现 |
| --- | --- |
| 单一职责节点 | 任务卡是**一个**可聚焦节点（「微信读书，备注：读完第三章，2 行，未完成」+ 动作列表），完成控件是**另一个**独立节点，二者语义不重叠（规格 §7「任务卡与独立完成控件避免重复或互相遮挡的语义节点」） |
| 装饰隐藏 | 插画、状态条、纸纹、呼吸点、分隔线一律 `Modifier.clearAndSetSemantics {}` 或 `contentDescription = null` |
| 顺序 | 用语义树顺序 = 视觉顺序；不使用 `traversalIndex` 反转。今天页顺序：日期 → 情绪锚点 → 封面摘要 → 计时状态卡（若有） → 临时组标题 → 临时任务 → 日常组标题 → 日常任务 → 折叠区标题带 → 折叠区内任务 → FAB |
| 标题角色 | 区块标题用 `semantics { heading() }`，使 TalkBack 支持按标题跳转（规格要求"正确顺序"；`heading()` 是 Compose 原生能力） |
| 动态播报 | 只对**离散状态变化**用 `LiveRegion.Polite`（完成、启动、暂停、选中热力格）；**不**对每秒计时用 |
| 弹窗焦点 | 确认弹窗/全屏页出现时 `focusRequester.requestFocus()` 移到弹窗标题；关闭后焦点**返回原触发元素**（规格 §7） |
| 长标题完整读音 | 卡片 `contentDescription` 用**完整标题**（不截断），配合视觉上的 2 行省略号；`Text` 自身也保留完整文本供 `onNodeText` 读取 |

### 6.3 焦点管理

| 场景 | 行为 |
| --- | --- |
| 打开模态底部抽屉（新建任务/补记投入/密码设置） | 焦点进入抽屉标题 → 第一个输入框；关闭后返回触发它的 FAB 或条目 |
| 打开全屏确认（跨日完成/时区变更/备份替换） | 焦点进入弹窗标题（不是第一个按钮，避免误触不可逆操作）；关闭后返回触发元素 |
| Snackbar 出现 | **不**抢焦点（会把用户从当前位置拽走）；「撤销」可用 TalkBack 手势按顺序到达 |
| 列表项被删除/完成移走 | 焦点移到**相邻**项目，不落回列表顶部 |
| 拖动排序的替代操作完成后 | 焦点保持在原任务卡上（该卡已换位置） |
| 页面转场（tab 切换） | 焦点移到页面标题 `heading()` |

**产品语义红线**（规格 §7 + 视觉提示词「禁止行为」）：

- **归档 ≠ 完成**：归档用 `ic_archive` + 「已归档」；两状态视觉与文案都不可互换。
- **计时投入 ≠ 该日完成**：投入只在时间账本表达；完成只看勾选事实。统计页不得出现「有效学习 X 小时」式未确认夸奖（原则 P6）。
- **漏做不惩罚**：漏做在记录页只用中性灰 + 「未记录」；**不**用红色、**不**用角标、**不**在首页显示"昨天欠 3 项"。
- **不做**连续打卡奖励、连续天数火焰图标、进度条惩罚。
