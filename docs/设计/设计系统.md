## 1. 视觉主张与可检验的设计原则

**主张**：应用像一本当代艺术家工作手册——展签式日期、编辑式文字编排、经过编辑的鲜明插画。视觉表达投入与持续行动，不做游戏化打卡羞辱。[设计默认，方向遵循 Q4 已确认的「D. 鲜明艺术插画」]

七条可检验原则（每条给出违反判据，便于评审与后续回归）：

| # | 原则 | 违反判据（评审可直接判） |
| --- | --- | --- |
| P1 | **纸上有展品**：容器宁静（奶油纸／浅白），重点作品与行动按钮鲜明 | 出现满屏无差别渐变、磨砂玻璃叠层、大面积低对比灰字 |
| P2 | **任务优先于装饰**：首屏不被大幅装饰遮蔽任务与「开始」入口 | 装饰元素把任一未完成任务的标题顶出首屏 |
| P3 | **一处焦点**：每屏只有一个最高互动权重元素（今天是运行中的计时或下一件事） | 同屏出现两个同权重实心赭红主按钮 |
| P4 | **状态不靠颜色独担**：每个状态至少有「颜色＋形状／纹样／文字／图标」中两项 | 存在仅靠色相区分、且无文字或形状辅助的状态对 |
| P5 | **图文不互相干扰**：文字区必有稳定纯色底或已达标的遮罩，换图不影响可读 | 任一标题落在未遮罩插画上且对比度 < 4.5:1 |
| P6 | **动作说话**：不写「你有 X 小时有效学习」这类未确认的夸奖，不用红色制造拖延焦虑 | 出现连续打卡奖励、惩罚性角标、未确认区间被计为投入的展示 |
| P7 | **动效解释空间**：动画保持空间连续性，只动少数元素；不影响点击命中 | 高频列表整屏动画、动画期间点击被吞、无减少动画等价反馈 |

### 2.4 色彩禁用清单

- 赭红 `#B64931` **不得**作为插画、渐变、半透明或图片之上的正文色。在 `canvas` 上刚好 4.64:1，任何叠层都会击穿 4.5:1。落在插画上时改用白色（需先满足 §8.5 遮罩）或在纯色底上改用 `accentDeep`。[设计默认｜视觉提示词第 36 行]
- 夜幕 `accent`（`#E0705A`）与 `accentFill`（`#C0553C`）不可互换：前者是文字色（4.79:1 on card），后者是实心底（配白字 4.56:1）。把它们对调即失败。
- 不使用纯黑 `#000000` 作夜幕底色；深色下的「更暗」用 `canvas → surfaceTint` 的亮度递降表达。
- 不用红色表达「漏做」「拖延」「欠账」。漏做在记录页用中性灰 + 文字「未记录」，不是红色失败标记。[源：规格 §4.1、Q5/Q6；视觉提示词「禁止惩罚性角标」]
- 深色与浅色下 `accent` 都用于**行动**；`running`（青绿）用于**进行中的计时**。二者不可混用，否则「运行中」与「可点击」会互相污染语义。

### 2.5 热力图六态编码

规格要求「色阶至少区分零值与非零投入，非仅凭颜色传递信息」「空日期展示 0，不能把没有任何当日任务记录当作任务完成失败」。因此定义 **6 类格子**，全部带非颜色线索：

| 状态 | 语义 | 浅色填充 | 边框 | 非颜色线索 | TalkBack |
| --- | --- | --- | --- | --- | --- |
| 无记录 | 该日无任何当日任务记录 | 无填充 | 1dp **虚线** `#8C7C63` | 虚线轮廓 | 「2026年3月4日，无记录」 |
| 零值 | 该日有记录或当日实例，但有效投入 0 秒 | 实心 `#E6DED0` | 无 | 实体填充 vs 虚线 | 「2026年3月4日，投入 0 分钟」 |
| 色阶 1 | 投入 1–29 分钟 | `#A2C8C2` | 无 | 图例数字区间 + 选中格直接标数字 | 「…投入 12 分钟」 |
| 色阶 2 | 30–59 分钟 | `#5E9993` | 无 | 同上 | 「…投入 45 分钟」 |
| 色阶 3 | 60–119 分钟 | `#256560` | 无 | 同上 | 「…投入 1 小时 30 分钟」 |
| 色阶 4 | ≥120 分钟 | `#093E3B` | 无 | 同上 | 「…投入 2 小时 5 分钟」 |

夜幕对应填充：`#1B3F39` / `#286056` / `#387F74` / `#5AA398` / `#97CEC2`；虚线 `#8A9AA4`。

**每格 2dp 画布色 gutter**，格子永不互相接触——这使边界不承担信息，从而不需要 3:1 的格间描边（单个描边色无法同时对 `#E6DED0` 与 `#093E3B` 达到 3:1，数学上不可行，故不做该假设）。零值↔色阶 1 的相邻填充比仅 1.36，因此**必须**保留「零值／无记录」的实心-虚线区分，不能只靠填充深浅。

## 3. 中文排版体系

### 3.1 字体族决策

| 用途 | 决策 | 依据与边界 |
| --- | --- | --- |
| 中文正文与标题 | **系统 CJK 字体族**（`FontFamily.Default` 解析到设备 CJK 字体），不打包第三方字体、不远程加载 | 视觉提示词第 31 行要求「不依赖远程字体下载」；本地无任何字体文件、无字体授权证据，打包未知授权字体不可接受。设备差异导致的字形差异记为**已知限制**（§13） |
| 拉丁与数字 | **Roboto**（Android 平台默认） | 与系统 CJK 字体同平台，字重体系一致（可同时取得 400/500/600/700） |
| 计时数字 | Roboto 数字 + **等宽数字特性**（`FontFeatureSetting("tnum")`） | 视觉提示词第 31 行「数字计时可用独立可读的等宽数字」；等宽保证秒位跳动时不产生横向抖动 |
| 大标题字重差 | 中文 700 + 拉丁 700，字距不加宽；情绪锚点用「大字号 + 大字距上限 0.02em」 | 编辑式字重差优先，避免引入未授权字体 |

**为什么不用 Noto Sans CJK 命名**：`doc` 中无法证明设备必然解析到 Noto；写死 Noto 会在 OEM 设备上产生回退不一致的伪保证。因此规格写「系统 CJK 字体族」，并在 Compose 中**不**指定 `fontFamily` 名称，只用 `FontWeight` 与字号。这是可核查的：`Typography` 中不出现任何 `Font(R.font.*)`。

### 3.3 中西文混排规则

1. 中文与拉丁/数字之间留 **1/4 em 空隙**，实现方式用 Compose 的 `TextStyle` 排版或直接输入**半角空格**；不靠 `<span>` 样式补丁。
2. 中文标点用**全角**，不吞并相邻空隙；拉丁括号与中文混排用全角括号。
3. 数字与单位之间留半角空格：`25 分钟`、`1 小时 30 分`、`96.5`。计时显示 `01:24:36` 内**不**加空格（等宽对齐优先）。
4. 日期明确写年份：`2026 年 10 月 5 日 周一`；跨时区或跨时区纪元的历史明细额外标注原时区：`2026-03-04 23:50（Asia/Shanghai）`。
5. 不使用全大写英文做标题（CJK 语境下无对比价值）；不用斜体表示强调（中文字体斜体多为伪斜体），强调用字重或赭红。

### 3.4 行宽、换行、截断与长文本

| 内容 | 规则 |
| --- | --- |
| 任务标题（卡片） | 最多 **2 行**，`titleM` 16sp/24sp；超 2 行末尾省略号；**绝不**把标题压到 12sp 以下来塞进一行 |
| 任务标题（详情／专注页） | 最多 **3 行**，`titleL` 18sp/26sp；超出后整段可滚动，不截断到不可辨识 |
| 备注（卡片） | 最多 **1 行**，`bodyM` 14sp，省略号 |
| 备注（详情） | 不限行数，`bodyL` 16sp/26sp，容器内滚动 |
| 中文单行舒适行宽 | **16–22 字**（按 16sp 计约 256–352dp）；超过时改多行，不做超宽单行 |
| 英文长单词 | `softWrap = true` + 字符级换行兜底，避免右溢 |
| 统计任务名（占比图） | 图例内最多 2 行；超出用表格明细呈现全名，**不**缩到不可辨识 |

**长标题实测估算**（脚本原样输出，几何估算：CJK 1.000 em、Roboto 数字 0.5615 em、拉丁 0.520 em）：

| 示例 | 长度 | 16sp 单行 | 16sp × fontScale 1.3 上限 | 22sp |
| --- | --- | --- | --- | --- |
| `微信读书 30 分钟` | 10 | 122.3 dp | 159.0 dp | 168.1 dp |
| `读完《设计中的设计》第三章并整理笔记` | 18 | 288.0 dp | 374.4 dp | 396.0 dp |
| `整理考研数学错题本（第 3 章 中值定理与导数应用）` | 26 | 373.5 dp | 485.5 dp | 513.5 dp |
| 75 字符英文长句 | 75 | 578.2 dp | 751.7 dp | 795.1 dp |

360dp 屏内容宽 328dp ⇒ 18 字符中文标题在 16sp 下 288dp **可单行**；26 字符 373.5dp **必须换行**（2 行 = 747dp 距，卡片需容纳 2×24sp=48dp 文字区）。这是卡片高度按「2 行标题 + 1 行元信息」预留 88dp 下限的原因（§7 卡片规格）。

### 3.5 计时数字自适应阶梯

计时数字是本应用唯一每秒变化的元素（视觉提示词要求「每秒更新的数字只影响计时区域」）。定义"优先大、放不下就降档"的阶梯，避免大字体下溢出：

| fontScale | 52sp | 44sp | 40sp | 36sp | 32sp | 选用 |
| --- | --- | --- | --- | --- | --- | --- |
| 1.00 | 204.3 | 172.9 | 157.2 | 141.4 | 125.7 | **52sp** |
| 1.30 | 265.6 | 224.7 | 204.3 | 183.9 | 163.4 | **52sp** |
| 1.50 | 306.5 | 259.3 | 235.7 | 212.2 | 188.6 | **52sp** |
| 1.85 | 378.0 ⚠ | 319.8 | 290.7 | 261.7 | 232.6 | **44sp** |
| 2.00 | 408.6 ⚠ | 345.8 ⚠ | 314.3 | 282.9 | 251.5 | **40sp** |

（单位 dp，`HH:MM:SS` 形态，可用宽度 328dp = 360dp − 16dp×2；⚠ 表示溢出。）

- 不足 1 小时时改用 `MM:SS` 形态：52sp 最宽 262.7 dp（fontScale 2.0），永不溢出，可直接锁 52sp。
- fontScale **超过 2.0** 时降到 36sp 并允许换行成两段（`01:24` / `36`），**不**做横向滚动（滚动数字不可读）。
- 档位切换在 `fontScale` 变化时重算，不在每秒 tick 中重算（每秒只改文本，不重排）。

### 3.6 大标题降档（原型实测后新增）

同样出于「大字号下装饰不得挤出任务」的约束，**28sp 及以上的标题档在大字号下必须设上限**：

| token | 上限 | 生效点 | 依据 |
| --- | --- | --- | --- |
| `displayXL`（40sp） | 56px | fontScale ≥ 1.4 | 仅在可折叠收起的大数字位使用 |
| `displayM`（28sp） | **44px** | fontScale ≥ 1.57 | 时间戳/日期块，不降档会独占首屏 |
| `headlineL`（26sp） | 40px | fontScale ≥ 1.54 | 空态主标题 |
| `headlineM`（22sp） | **36px** | fontScale ≥ 1.64 | 情绪锚点、区块大标题 |
| `headlineS` 及以下 | 无上限 | — | 20sp × 2.0 = 40px 可接受，且是任务/区块标题，属内容 |

**为什么不违反无障碍**：WCAG 2.2 对文字缩放只设下限（不缩到不可读）不设上限；用户选择「大字体」的意图在**内容文字**上完整保留——任务标题 16sp × 2.0 = 32px、备注 16sp × 2.0 = 32px 均**不降档**。设上限的只有装饰性与结构性大标题。此规则是与「任务必须留在首屏」权衡后的设计默认，**真机评审时可据实际观感调整上限值**。

### 3.7 封面在大字号下的让位闸门

与 §3.6 配套：`cover` 画幅在 fontScale 放大时按档收窄，**2.0 档整块让位**（含封面摘要）。完整实测数据与规则见 `docs/设计/关键页面高保真说明.md` §1.4。

**验证状态**：
1. 上表由 `scripts/test/verify_design_tokens.py` 按静态字宽假设算出（CJK 1.000 em、Roboto digit 0.5615 em、colon 0.280 em），**未在真机测量实际栅格化宽度**；OCR 与布局引擎的字距调整可能造成 ±3% 偏差，真机复核列为 §13 的待验证项。
2. 该阶梯**已在原型中落地并演示**（本轮之前它只是规则、原型把 `.focus-big` 写死成 52px）：`docs/设计/视觉原型.html` 的 `applyTimerLadder()` 复刻同一张离散档位表，专注页新增「运行中 + 大字体 2.0」状态，并在计时数字下实时标注所选档位与占用宽度。桌面 Chromium 实测：
   - fontScale 1.00 → 选用 **52sp**，`01:24:36` 占用 204dp / 可用 328dp；
   - fontScale 2.00 → 降到 **40sp**（computed 80px），占用 314dp / 可用 328dp，不溢出。
   门禁断言「运行中+大字体时计时数字降档」「降档后不溢出手机宽度」「暂停/结束按钮无需滚动即可见」
   （2.0 档下进度环 200px 会把控制按钮推到导航栏之下 51px，故环在大字号下收缩到 140px、2.0 档隐藏——环是装饰，按钮是操作目标）。

### 4.1 基础节奏

- 基础单位 **8dp**；允许 **4dp 半档**，仅用于图标与文字基线对齐、标签内边距。

### 4.2 栅格与安全区

## 5. 材质与光影

### 5.1 纸纹（`paperGrain`）

- 实现：确定性生成的 64×64px 透明 PNG/noise 纹理，`alpha` 全域 **0.03**（浅色）／**0.05**（夜幕），平铺于 `canvas` 与 `surfaceCard`。
- 生成方式：以固定种子在构建期生成并入库（不依赖运行时随机），保证同一 APK 每次渲染一致、截图回归可比。
- 关闭条件：**系统「减少动画/移除动画」开启时保留纸纹**（它是静态纹理，不影响前庭）；但**低电量模式下关闭纸纹**（省电模式下减少一次全屏纹理合成）。
- 纸纹**绝不**叠在插画上（会削弱丝网质感并降低文字对比度），只作背景层。

### 5.2 层级表达

层级用 **亮度 + 1dp 描边**表达，不用重投影：

| 层级 | 浅色 | 夜幕 |
| --- | --- | --- |
| 底 | `#F5F0E8` + 纸纹 | `#0F1720` + 纸纹 |
| 卡片 | `#FFFFFF`，1dp `#DDD3C2` | `#1B2733`，1dp `#3B4A57` |
| 抬升（浮层/操作条） | `#FBF8F2` + 阴影 `0 8dp 24dp rgba(25,44,59,0.10)` | `#22303D` + 光晕 `0 -1dp 0 0 rgba(255,255,255,0.06)` |
| 选中 | `#FBEFEA` 底 + `#B64931` 2dp 边 | `#3A2018` 底 + `#E0705A` 2dp 边 |

**禁用**：磨砂玻璃（`blur`）叠满、多层半透明渐变容器、「投影越重层级越高」的两套语义。

### 5.3 单光源

插画与阴影共用**左上 45° 单一光源**。插入到页面里的插画，其光照方向必须与卡片阴影一致；不一致的素材视为不合格（评审判据 P5 的扩展）。

## 7. 插画体系

### 7.1 绘画语言（约束，非描述）

- 有限调色：每幅最多 **4 个色相**（从 §2.1 的赭红/青绿/钴蓝/柠黄/赭金中选 3，加纸色），加上黑与白。
- 明确轮廓：物体描边 2–3px（在 1024px 画布上），圆头端点。
- 自然物／纸片几何叠层：2–4 层，层间有 1–2px 错位制造手工感。
- 轻纸纹或丝网印刷颗粒：颗粒只出现在**色块内部**，不出现在文字安全区。
- 局部柔和空间光：最多一处，且不得落在文字安全区。
- **禁止**：写实摄影、渐变网格、霓虹发光、通用图标式扁平插画、任何第三方可识别品牌元素或角色。

### 7.2 画幅与安全区

每幅素材提供三种画幅，且**每种画幅都单独记录安全区元数据**：

**画幅契约以 `assets/art/scrim/*.json` 为准**（作者已交付，逐幅给出 `canvas.widthPx/heightPx/dpW/dpH`）。
下表各帧尺寸即为该 JSON 声明的值，页面容器必须与之一致，否则素材自带 `safeText` 与遮罩停位不再对齐：

| 画幅 | 尺寸（1x 逻辑 / 2x 像素） | 用途 | 文字安全区（来自 scrim JSON） |
| --- | --- | --- | --- |
| `cover` | **328×200dp / 656×400px** | 今天页今日封面 | `safeText` y 0.64–1.0（底部 72dp），强区 α 0.86 |
| `card` | **72×72dp / 216×216px** | 任务卡左缘缩略 | 无文字（缩略图不含文字） |
| `panel` | **328×160dp / 656×320px** | 空态、异常恢复、洞察标题 | `safeText` y 0.40–1.0（底部 96dp），强区 α 0.86 |

**页面用值必须等于契约值**。以下两处曾与契约不一致，已按契约改正（见 §12.4）：
今天页空态曾写「画幅同 328×168dp」而 `empty_today.json` 是 656×320（=328×160dp）；
洞察页标题插画曾写 328×120dp，而 `chart_heatmap.json` 是 656×320——按 120dp 高 `Fit` 会把素材缩到
约 246×120 并两侧补纸色，遮罩与素材自带安全区错位。今日封面同理：设计系统原写 200dp、关键页面按首屏预算
写 168dp，现已统一为契约值 **200dp**，首屏预算随之重算（关键页面说明 §1.1）。

安全区元数据以 `assets/art/scrim/<name>.json` 交付，字段：`canvas`、`scrimStops`（0–1 归一化位置 + alpha）、`safeText`（矩形，归一化）、`dominantColors`（最多 3 个 HEX，供 Compose 计算遮罩兜底色）、`minContrastOnScrim`（素材自身在遮罩上允许的最低对比度）。

**每幅素材必须**由作者自证：把 `safeText` 区域按 `scrimStops` 叠加后，白色或 `#F2EDE4` 文字的合成对比度 ≥ 4.5:1。自证方法不限（脚本或截图测量），但结论要写进 `素材适配样例.md`。**该自证已完成**（插画创作员补记 2026-10-05）：9 幅 cover/panel 素材按 `scrimStops` 对真实光栅逐行合成后，浅色白字最低 8.44:1、夜幕暖白字最低 8.16:1，全部 ≥ 4.5:1；命令 `python scripts/test/verify_art_assets.py`，原样输出见 [素材适配样例](素材适配样例.md) §3.2。这是作者侧证据；**我方仍未在 Android 设备上渲染核查**。

### 7.5 遮罩与文字保护（实测数值）

浅色主题遮罩用 `#192C3B` 叠层（结果见 §2.3 表）。**实际停位以 `assets/art/scrim/*.json` 的 `scrimStops` 为准**——
`cover` 帧是 **5 档**（0 / 0.18 / 0.38 / 0.54 / 0.66 / 1.0），`panel` 帧是 **4 档**（0 / 0.20 / 0.40 / 1.0）；
本节早前把封面写成「三段渐变」是描述性简化，与 JSON 不一致，已按 JSON 更正。四条硬规则：

1. **强区**（α 0.86）可承载任意字号 ≥12sp 的白字（最差 9.18:1）。
2. **中区**（α 0.72）可承载 ≥12sp 白字（最差 5.82:1）。
3. **弱区**（α 0.52，仅 `cover` 帧在 y 0.38–0.54 出现）**只允许** ≥24sp 大字（最差 3.21:1），且不可承载正文。
4. 若素材的 `minContrastOnScrim` 自证失败，则该素材**不得**用于任何文字叠加位，退回纯展示缩略图。

夜幕遮罩用黑色叠层 α 0.72/0.82，配 `#F2EDE4`（最差 7.97:1），可承载任意字号。

### 7.6 退化视觉（图片缺失／加载失败）

规格要求「图像加载失败或资源不存在有设计完整的退化视觉，不出现空白闪烁」。三级退化：

1. **占位**：固定尺寸容器先画 `surfaceTint` 底 + `paperGrain`，尺寸与正常态**完全一致**（不留 CLS）。
2. **失败**：绘 `placeholder_missing.svg`（被撕去一角的纸）于容器内，`ContentScale.Fit` 居中。
3. **兜底文案**：容器下方 `labelM`「插图暂不可用」，`inkTertiary`。**任务标题、备注、完成控件、开始按钮位置与尺寸不变**，全部保持可操作。

退化态也会出现在 `placeholder_missing.svg` 本身缺失时：此时画 `surfaceTint` + `ic_image_broken` 40dp 图标，功能不减。

### 7.7 性能约束

- 列表中的缩略图使用 `thumbs/*_thumb.webp`，显示尺寸 ≤72dp ⇒ 预解码目标 ≤216px 宽（3x）。
- 封面按 328×200dp 解码目标 ≤656×400px（2x），**禁止**把 2048px 原图整幅进内存。
- 使用固定尺寸容器 + 显式 `ContentScale`，避免测量阶段二次解码。
- 缓存上界：内存图片缓存 ≤ 32MB 或 40 项（取小者），LRU 淘汰。
- 列表滚动期间不启动新解码（`LazyListState.isScrollInProgress` 门控）。

这些是**设计约束**，具体实现与真机内存/帧指标见规格 §10 与「未验证」清单（§13）。

## 9. 无障碍基线（设计侧）

- 正文 ≥4.5:1、大字 ≥3:1、图标与控制边界 ≥3:1：已由 §2.3 的 77 项正向检查 + 4 项反向禁检覆盖；**真机渲染与插画叠层未验证**。
- **主要触控目标 ≥48×48dp**；相邻可点目标间距 ≥8dp；`ic_drag` 把手视觉 24dp 但命中区 48dp。
- 支持系统字号缩放至 2.0（§3.5 已有计时数字与标题的换行策略）；支持「显示大小」改变时按 dp 布局自动适配，不出现横向滚动。

- 热力图有语义索引与表格明细；图表有表格化替代。

## 10. Compose 落地映射

### 10.1 主题骨架

单一 `StudioTheme` 承载全部 token；**不使用** Material 默认配色、**不使用**动态取色（`dynamicColor`），否则品牌色与对比度门禁全部失效。

```kotlin
// Design-system entry point. Tokens live in StudioTokens; Material slots are derived,
// never hand-picked per screen.
@Composable
fun StudioTheme(
    darkTheme: Boolean = isSystemInDarkTheme(),
    content: @Composable () -> Unit,
) {
    val tokens = if (darkTheme) StudioTokens.Night else StudioTokens.Day
    CompositionLocalProvider(LocalStudioTokens provides tokens) {
        MaterialTheme(
            colorScheme = tokens.toColorScheme(),
            typography = StudioTypography,
            shapes = StudioShapes,          // NOT the default M3 shape scale
            motionScheme = tokens.motion,   // only if the pinned BOM exposes it
            content = content,
        )
    }
}
```

**MotionScheme 风险（必须按此处理）**：本工程锁 `material3 = 1.4.0`（`docs/设计/工程布局与版本锁定.md:221`、`:245`）。我**无法本机核实** 1.4.0 是否暴露稳定的 `motionScheme` 参数：本地 Gradle/Maven 缓存中不存在 `material3` 制品（`find ~/.gradle -iname "material3*1.4.0*"` 无输出），而官方 release 页面在我抓取到的内容里只提到 `1.5.0-alpha27` 移除已废弃的 `LocalMotionScheme` 并改用 `MaterialTheme.motionScheme`，**没有**给出 1.4.0 的 API 清单（来源：`https://developer.android.com/jetpack/androidx/releases/compose-material3`，抓取结果明确表示未包含 1.4.0 release notes）。

因此规定：

1. 阶段 C 首次可编译时，先用编译期验证该参数是否存在（写一行 `MaterialTheme(motionScheme = ...)`，编译不过即不存在）。
2. **无论结果如何**，我方 §8 的动效时长/曲线都**不依赖** MotionScheme，而是直接从 `StudioTokens` 取 `tween`/`spring` 规格。MotionScheme 存在则作为系统级默认补充，不存在功能缺口。
3. 不得为了用上 MotionScheme 而升级 Compose BOM 到 2026.08.00+（会要求 compileSdk 37，本机不具备，见版本锁定 §5.2）。

### 12.1 首轮门禁发现的失败项与本轮处置

`scripts/test/verify_design_tokens.py` 首次运行时 **4 项 FAIL**（仅影响热力图格子边界）：

```
浅色 零值环 / 零值格  #CBBFA9 on #E6DED0 = 1.36:1 < 3.0
浅色 无记录环 / 画布  #B5A78D on #F5F0E8 = 2.09:1 < 3.0
夜幕 零值环 / 零值格  #3B4A57 on #1B3F39 = 1.27:1 < 3.0
夜幕 无记录环 / 画布  #526070 on #0F1720 = 2.81:1 < 3.0
```

**处置（未降低阈值）**：先证明"单一描边色同时满足对 `#E6DED0` 与 `#093E3B` 的 3:1"在数学上不可行（需同时 `L ≤ 0.2121` 与 `L ≥ 0.2146`），据此改变编码方式而非放宽阈值——① 每格 2dp 画布色 gutter，格子永不接触，格间边界不再承载信息；② 「无记录」改为虚线轮廓 `#8C7C63`（浅色，对画布 3.57:1、对零值格 3.04:1）／`#8A9AA4`（夜幕，对画布 6.22:1、对零值格 3.98:1）；③ 零值 vs 无记录改由「实心 / 虚线」承担，不再依赖浅色差。

### 12.2 第二轮：违禁组合断言自身的失败

第二轮加入「违禁组合必须低于阈值」的反向断言后，首次运行 **1 项 FAIL**：

```
违禁组合意外达标: 禁止：浅色 accent 文字 / accentTint 底（小字）  #953C28 on #FBEFEA = 6.31:1 < 4.5
```

**处置**：`accentDeep` 在 `accentTint` 上实测 6.31:1，是**达标**组合，我原先把它写成禁令本身就是错的。修正为四条真实成立的禁令（浅色 accent/插画亮橙 2.48:1、inkTertiary/surfaceTint 4.32:1、夜幕 accent 实心底白字 3.17:1、accentDeep/heat.2 2.18:1）。**没有**通过放宽阈值或删除断言来让它变绿。
