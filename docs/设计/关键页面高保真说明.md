# 关键页面高保真说明

> 对象：Android 个人艺术 Todo 与专注计时。本文件是**阶段 B 的可审阅高保真说明**，逐页给出构图、层级、状态矩阵、可读性处理与触控目标。视觉 token（颜色值、字号、间距、圆角）一律引用 `docs/设计/设计系统.md`，本文件不重复定义数值。
>
> 依据：`docs/需求/艺术视觉与交互开发提示词.md`「需要逐屏设计的体验」表与「失败与极端状态」段；`docs/需求/Android个人艺术Todo开发需求规格.md` §2 导航表、§4–§6 行为规则、§7 艺术视觉与交互品质。
>
> 目标形态：**Android 手机竖屏**（360×800dp 逻辑 / 1080×2400 @3x）。小屏 320dp 与横屏按每页声明的降级规则处理。
>
> 触控目标：**所有主要操作目标 ≥48×48dp**（规格 §7、视觉提示词第 70 行）。本文件每页给逐元素表。
>
> 状态覆盖要求（视觉提示词「失败与极端状态」）：图源缺失、零统计、长任务名、超长备注、大字号、折叠区数十项、错误密码、通知权限拒绝、备份空间不足、时钟异常、进程重建都必须有界面与可恢复动作。本文件按页覆盖，总览见 §6。
>
> 当前状态：这是**设计说明与数值规格**，不是实现、不是截图。真机渲染、TalkBack 朗读、大字号实测、图片缺失实测均**未执行**（§8）。

## 0. 全局约定

### 0.1 底部导航

| 项 | 规格 |
| --- | --- |
| 目标 | 固定 4 个：今天 / 记录 / 洞察 / 设置（规格 §2「最多四个稳定底部入口」） |
| 高度 | 80dp + `navigationBars` inset；**不**为专注另设第 5 个入口 |
| 图标 / 标签 | 28dp 图标 + `labelM` 12sp 文字；图标与文字间距 4dp |
| 触控目标 | 每项命中区 ≥ 82dp 宽 × 80dp 高（远超 48dp） |
| 选中表达 | 图标填充变体 + `accent` 色 + `labelM` 字重 600；**三重**，不只靠颜色 |
| 未选中 | `inkTertiary` 图标 + 文字 |
| 进行中的专注 | 不占导航位；由「今天」页顶部持续状态卡承载，点按回到专注全屏 |
| 横屏 / 展开 | 改用 `NavigationRail`（宽 96dp，左置），内容区最大 640dp 居中 |

### 0.2 页面层级（z-order，五个页面统一）

```
① 底部导航栏（常驻，最高，不可被内容遮挡）
② FAB / 底部操作条（浮于导航之上 16dp）
③ Snackbar 撤销条（浮于 FAB 之上，向上偏移其高度 + 8dp）
④ 弹窗 / 底部抽屉（ModalBottomSheet）
⑤ 全屏确认（跨日完成日期选择、异常区间确认、备份替换警示）
⑥ 页面内容（LazyColumn / LazyVerticalGrid，含顶部 inset 消费）
```

页面按 `⑥→⑤→④→③→②→①` 从底到顶绘制；Snackbar 出现时 **FAB 上移**而非遮挡（避免「撤销」与「新建」命中区重叠）。

### 0.3 共享组件：任务卡（`StudioTaskCard`）

卡片是五个页面里唯一被大量复用的容器，规格要求「临时/日常区、完成态/未完成态、计时中/暂停、插画明暗变化均具有明确视觉区分」且「文字区域有稳定纯色或足够的遮罩」。

| 元素 | 规格 |
| --- | --- |
| 卡片尺寸 | 宽 = 屏宽 − 16dp×2（328dp @360dp）；高 **88dp**（2 行标题）/ **72dp**（1 行标题） |
| 卡片底 | `surfaceCard`，1dp `lineHairline` 描边，`radius.lg` 16dp |
| 插画位 | 72×72dp，距卡片左/上 8dp，`radius` 12dp（左上角受控降为 3dp 制造贴纸感）；`ContentScale.Crop` |
| 文字区 | 距插画右 12dp；**宽度 180dp @360dp**（= 328 − 8 − 72 − 12 − 48 − 8） |
| 标题 | `titleM` 16sp/24sp/600，最多 2 行，末行省略号 |
| 备注提示 | 有备注时标题下 4dp 显示 `bodyM` 14sp/22sp/400 单行 + 尾部 `ic_note` 16dp |
| 完成控件 | 视觉空心圆 24dp；**命中区 48×48dp**，位于卡片右侧，外边距 8dp |
| 状态条 | 计时中/暂停时卡片左缘出现 4dp 竖条（`running` 实线 / `inkTertiary` 虚线），卡片高度不变 |
| 拖动把手 | 命中区 48×48dp，视觉 24dp 6 点图标，位于卡片左缘（插画左侧）8dp 处；**在插画左侧会挤占文字区**，故实际操作放在长按菜单中（§0.5） |
| 点按语义 | 整卡点按 = 打开详情与模式选择；完成控件是**独立语义节点**，不与整卡重叠（规格 §2「不能把打开卡片误触为完成」） |

**可读性处理**：插画只占 72dp 见方，文字全部落在 `surfaceCard` 纯白（浅色）/ `#1B2733`（夜幕）纯色上，**不叠任何文字于插画之上**。因此任务卡不依赖遮罩满足 4.5:1；实测 `ink`/`surfaceCard` = 14.34:1（浅色）、13.01:1（夜幕）。

### 0.4 共享组件：进行中状态卡（`StudioRunningBar`）

| 元素 | 规格 |
| --- | --- |
| 位置 | 今天页首项，展签日期与封面**之后**、任务列表之前（保证「首屏能看到正在进行」） |
| 高度 | 64dp（宽同卡片） |
| 内容 | 左 `running` 4dp 竖条；任务名 `titleM` 单行；右侧计时 `displayL` 34sp 等宽数字；`running` 呼吸点 8dp（唯一循环动画，减少动画下改为静态实心点） |
| 触控目标 | 整卡 ≥ 64dp，右侧「回到专注」按钮 48×48dp |
| 点按 | 进入专注全屏，**不**新建会话（规格「首页/通知可回到同一状态，不创建第二计时器」） |
| 语义 | 单个语义节点：「微信读书，进行中，已投入 24 分 36 秒，点按返回专注」 |

### 0.5 排序替代操作（拖动之外）

拖动排序必须提供单指/读屏替代（WCAG 2.2 SC 2.5.7）。任务卡的 `ic_more` 菜单（48×48dp）中固定包含：

```
上移           → 与同组前一项交换，Snackbar「已上移」
下移           → 与同组后一项交换，Snackbar「已下移」
移到组首 / 移到组末
编辑标题与备注
归档
```

「上移/下移」是**一级菜单项**，不藏二级。TalkBack 聚焦卡片时自定义动作列表同样暴露「上移/下移」（详见 `docs/设计/动效与无障碍说明.md` §5）。

## 1. 今天

定位：应用默认首页（规格 §1「启动能识别今天该做什么」）。首要信息：日期与情绪锚点 → 临时未完成 → 日常未完成 → 已完成折叠区 → 新建入口。

### 1.1 构图与首屏预算

```
┌─ statusBars inset 24dp ────────────────────────────┐
│ 12dp                                               │
│ 展签日期块  28sp「2026 年 10 月 5 日 周一」   [ic_zone 24dp] │
│ 8dp                                                │
│ 情绪锚点    22sp「今天有三件事在等你」              │
│ 16dp                                               │
│ 今日封面    328×200dp  radius 24dp（= 契约值）      │
│   └ 底部 72dp 遮罩：18sp 白字摘要 + 朱砂日期戳     │
│ 16dp                                               │
│ 区块标题 20sp「临时任务」  右侧「2 项」            │
│ 8dp                                                │
│ 任务卡 88dp  ───────────────────────────────────   │
│ 8dp                                                │
│ 任务卡 88dp  ───────────────────────────────────   │
│ 8dp                                                │
│ 任务卡 88dp  ───────────────────────────────────   │
│ 8dp                                                │
│ （继续滚动）区块间距 32dp                          │
│ 区块标题 20sp「日常任务」  右侧「4 项 · 已投 1 小时 12 分」│
│ ...                                                │
│ 32dp                                               │
│ 折叠区标题带 48dp「已完成 3 项」  [ic_expand 24dp] │
│ ══ 底部导航 80dp + navigationBars inset ══          │
└─ FAB 56dp（右下，上距底栏 16dp，右距 16dp）────────┘
```

**首屏预算（360×800dp 逻辑屏，逐项相加）**：

| 行 | dp |
| --- | --- |
| `statusBars` inset + 12dp 顶距 | 36 |
| 展签日期块（36 行高 + 8 + 30 锚点 + 16 下距） | 90 |
| 今日封面 200dp + 下距 16dp | 216 |
| 区块标题行（28 + 8） | 36 |
| 任务卡 ×3 + 卡间距 ×2（88×3 + 8×2） | 280 |
| **首屏内容合计** | **658** |
| 可视高度（800 − 80 导航 − 24 `navigationBars` − 24 `statusBars`） | 672 |
| **剩余** | **14** |

结论：首屏完整显示「日期 + 情绪锚点 + 今日封面 + 临时组标题 + **3 张完整任务卡**」，并露出第 4 张的上沿。封面高度取契约值 **200dp**（原写 168dp 是为了塞下第 3 张卡而擅自压缩，与 `scrim/cover_*.json` 的 656×400 不匹配，已按契约改正；首屏因此只剩 14dp 余量，第 3 张卡仍在首屏内，第 4 张露出上沿大幅减少)——这是对原则 P2「首屏不能被大幅装饰遮蔽任务与开始按钮」的量化落地，而非感觉。

> **本表仅适用于 fontScale = 1.0。** 系统字号放大后封面按 §1.4 的闸门收窄或让位；§1.4 的表格给出了 4 个档位的实测数据。
> 原型验证据：`python scripts/test/verify_prototype_offline.py` 断言「今日封面高度 = 168px」「大字体下封面收窄或隐藏」「大字体首屏至少露出 1 张任务卡」。
> 说明：上表是**桌面浏览器原型**的量取结果，与 Android 真机的系统 inset、字体栅格化存在差异，真机复核见 §8。

### 1.2 层级（信息优先级自上而下）

| 层 | 元素 | 视觉权重手段 |
| --- | --- | --- |
| 1 | 进行中的计时（若存在） | `running` 色 + 4dp 竖条 + 秒级数字 = 最高互动权重 |
| 2 | 展签日期 + 情绪锚点 | `displayM` 28sp 主墨，无装饰 |
| 3 | 临时未完成组 | 排在日常之前（规格 §4.2「未完成临时任务固定在日常任务之前」） |
| 4 | 日常未完成组 | 同结构，区块标题区分 |
| 5 | 今日封面 | 第二焦点（规格「首屏只给当前进行中的计时最高互动权重，艺术图作为第二焦点」） |
| 6 | FAB 新建 | 唯一实心 `accent` 圆形按钮 |
| 7 | 已完成折叠区 | `surfaceTint` 带，弱化，处于折叠态 |

**同屏只有一处实心赭红**：FAB。任务卡的完成控件是空心描边，避免抢 P3「一处焦点」。

### 1.3 状态矩阵

| 状态 | 触发 | 界面表现 | 可恢复动作 |
| --- | --- | --- | --- |
| **空态** | 无任何任务（首次安装） | 展签日期块保留（日期是页面身份，不因空数据消失）；今日封面换成 `empty_today.svg`（空画架＋待写的纸），容器 328×160dp（= `empty_today.json` 契约值，**不是** 168dp）；下方 `headlineL` 26sp「今天还是一张空白的纸」+ `bodyL`「加入第一件事，或者先给自己定一段专注」；**唯一**主按钮「新建第一件事」实心 `accent`，高 56dp、宽占满内容区（328dp），距插画 24dp；按钮下方 `labelM`「也可以直接从下面开始专注」指向日常组空态 | 主按钮 → 新建；插画为装饰，无点击 |
| **满态（有任务）** | 临时 ≥1 或日常 ≥1 | §1.1 构图；区块标题右侧显示计数与当日投入（`inkTertiary` 12sp） | 整卡点按进入模式选择 |
| **折叠区展开** | 点折叠标题带 | 带展开为 `surfaceTint` 48dp 标题带 + 已完成卡列表；动画 240ms（§9 动效文档）；展开后「已完成」卡片标题用 `inkSecondary`，完成控件为**实心勾** | 点带收起；Snackbar「已收起」 |
| **折叠区数十项** | 已完成 >20 项 | 折叠区内部**独立** `LazyColumn`，最大高度 = 视口 60%（约 400dp）后自身滚动；标题带右侧计数始终可见，**不**一次性展开全部；`labelM`「共 37 项，可向上滑动」 | 滚动；点带收起 |
| **完成 / 撤销** | 点完成控件 | 该卡立即：完成控件变实心勾（120ms）、标题降 `inkSecondary`、卡片在 240ms 后移入折叠区；Snackbar「已完成『微信读书』」+「撤销」8s | 撤销返回原位置与顺序（规格 §4.2「尽量恢复它原来的手动顺序」）；Snackbar 消失后仍可在折叠区点实心勾撤销 |
| **计时中** | 有 Running 会话 | 状态卡插在展签与任务列表之间；对应任务卡出现 `running` 4dp 竖条与「进行中」标签 | 点状态卡 → 专注全屏 |
| **暂停中** | 有 Paused 会话 | 状态卡竖条改**虚线**，计时数字 `inkTertiary`，`labelM`「已暂停」，呼吸点静止 | 同上 |
| **跨日** | 会话跨过 00:00 | 展签日期按新日更新；运行中的计时**不重置、不中断**（规格 §5.3）；状态卡出现 `labelM`「本段从 23:50 开始，跨入今天」 | 无额外动作；投入按实际区间分归两日 |
| **异常恢复待确认** | 进程中断/重启后 | 状态卡改 `warnTint` 底 + `warnInk` 文字 + `ic_recovery`；文案「上次的计时可能没有正常结束。已确认 18 分 40 秒，另有 6 分 12 秒推算区间需要你确认。」；三个动作按钮：「接受」「修正」「舍弃」，各 ≥48dp 高；**待确认区间不进入统计**，状态卡下方 `labelM`「未确认的部分不计入投入」 | 三选一；不选则状态卡持续存在（不阻塞其他操作） |
| **大字体** | fontScale 2.0 | 见 §1.4「大字体闸门（原型实测修正）」——**初稿写的「封面高度不变、首屏任务数降为 1–2」是错的**，原型实测首屏任务数为 0 | 全部操作仍可达；FAB 不被内容遮挡 |
| **长标题** | 标题 >22 字符 | 卡片内 2 行截断（省略号）；`contentDescription` 与详情页给全名（`docs/设计/动效与无障碍说明.md` §4） | 打开卡片读全名 |
| **超长备注** | 备注 >200 字符 | 卡片内**只显示 1 行** + `ic_note`；详情页备注区可滚动，`bodyL` 16sp/26sp | 详情页编辑 |
| **图片缺失** | 封面/缩略图解码失败 | 封面位：`surfaceTint` + 同尺寸 `placeholder_missing.svg` + 下方 `labelM`「插图暂不可用」；任务卡缩略图：72dp 容器画 `surfaceTint` + `ic_image_broken` 24dp。**尺寸完全不变**，标题、完成控件、点按区域位置不变（规格 §7「图像加载失败或资源不存在有设计完整的退化视觉，不出现空白闪烁」） | 无需动作，功能不减 |
| **错误态** | 任务加载失败（Room 读取异常） | 展签保留；内容区替换为 `warnTint` 面板：`ic_warning` 40dp + `headlineS`「暂时读不到任务」+ `bodyL`「数据仍在设备上，没有丢失。可以重试。」+ 实心 `accent` 按钮「重试」；**不**显示空态插画（避免把错误说成「没有任务」） | 重试 |
| **新建中（键盘）** | 点 FAB | 底部 `ModalBottomSheet`：标题输入框（`titleM` 16sp，可见浮动标签「任务名称」）、备注输入框（`bodyL`，标签「备注（可留空）」）、类型选择（临时/日常，分段控件，每段 ≥48dp 高）、「添加」按钮 56dp。键盘弹出时整体上移，输入框底距键盘 16dp | 空标题时「添加」禁用且下方 `bodyL` `dangerInk`「请填写任务名称」；取消保留草稿 |

### 1.4 大字体闸门（原型实测修正）

初稿曾写「大字体下封面高度不变，首屏任务数由 3 降到 1–2」。用原型（`docs/设计/视觉原型.html`）在桌面
Chromium 里以 fontScale 2.0 实测后，**该写法不成立**，且比它更早的自我修正也有问题：第二轮把判据写成
「卡片顶部越过可视底 20px 即算可见」，实测那样卡片被底栏**截断 40%**（155px 只露 93px），
与文档「完整任务卡」的说法不符。现判据改为**整卡可见**。

实测证据（`python scripts/test/verify_prototype_offline.py`，断言「大字体首屏至少露出 1 张**完整**任务卡」）：

| 尝试 | 28sp 主标题 | 封面 | 复盘 |
| --- | --- | --- | --- |
| 初稿 | 不降档（56px） | 168dp 不变 | 首张卡 y=764 → **0 张完整** ✗ |
| 第二步 | 上限 44px | 96dp 收窄 | 首卡 y=673、可视底 631 → **0 张完整** ✗（还差 42px） |
| 第三步 | 上限 44px | 整块让位 | 首卡 y=538–693、可视底 631 → **截断 40%** ✗（旧判据却报「通过」） |
| **定案** | 上限 44px | **整块让位 + 移走手机内的演示注释条** | 首卡 y=344–499 → **1 张完整** ✓ |

第三行是这一步最重要的发现：**判据放宽会让失败看起来像通过**。演示用的注释条也一度放在手机屏幕内，
在 fontScale 2.0 下自己就占 128px；现全部移到手机外的 `.page-note`（不随字号缩放）。

因此定案为四档闸门。**这是设计规则，不是原型专属技巧**，Compose 实现需照此分支：

| 档 | fontScale | 28sp 主标题 | 22sp 情绪锚点 | 封面 | 封面摘要 | 首屏完整任务卡 | 区块标题行 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | < 1.3 | 28sp | 22sp | 200dp（契约值） | 叠在封面遮罩上（白字） | 3 张 | 单行 |
| 2 | 1.3–1.59 | 上限 44px | 上限 36px | 152dp | 叠在封面遮罩上 | 2 张 | 单行 |
| 3 | 1.6–1.99 | 上限 44px | 上限 36px | 112dp | **移出封面**，改用主墨落在画布纯色上 | 1–2 张 | 单行 |
| 4 | ≥ 2.0 | 上限 44px | 上限 36px | **整块让位** | **整块让位** | 1 张 | 单行（计数可省略号收缩） |

规则依据：

1. **大标题降档**（28sp 上限 44px、22sp 上限 36px）。不降档时日期块独占 217px，封面与任务全被推走。
   降档不违反无障碍——WCAG 只设下限不设上限，且用户可控的「大字体」意图在正文与任务标题上**完整保留**
   （16sp × 2.0 = 32px，不降档）。
2. **封面按档收窄，2.0 档整块让位（含封面摘要）**。封面是装饰，任务是可操作内容；
   与 P2「首屏不能被大幅装饰遮蔽任务与开始按钮」冲突时，装饰让位。2.0 档用户仍看到：
   展签日期、情绪锚点、两个任务组标题与至少 1 张**完整**任务卡。
3. **封面摘要在第 3 档起移出封面**。96–112dp 高的封面装不下 2 行大字；硬叠会裁字并与日期戳重叠
   （原型中出现过，已修正）。
4. **封面摘要在第 4 档一并让位**。它是装饰性文案，不是用户内容；用户自己写的标题与备注
   在任何档位都完整显示、不截断。
5. **区块标题行必须单行**。2.0 档下标题与右侧计数曾挤成两行（实测 112px 高）。现标题 `nowrap`、
   计数不再随字号放大且可省略号收缩——计数是参考信息，不是内容。
6. **2.0 档隐藏封面意味着「今日封面」当天不可见**——可接受，因为封面不承载用户数据；
   记录页与洞察页仍可看到全部插画。

**日历格子编码**（不用红/绿表示好坏）。

**关键结构决定：日期数字不叠在色阶填充上。** 每格是一个纵向单元 = 日期数字 + 色块；
数字落在 `canvas` 纯色上（`ink`/`canvas` = 12.64:1），色块只承载投入档位。

为什么不能把 14sp 数字直接压在色块上（以下为 `python scripts/test/verify_design_tokens.py` 的实测值）：

| 组合 | 实测 | 结论 |
| --- | --- | --- |
| `ink` / `heat.2` | **4.41:1** | 低于 4.5:1，不合格 |
| `ink` / `heat.3` | **2.12:1** | 不合格 |
| `ink` / `heat.4` | **1.20:1** | 不合格 |
| 白字 / `heat.2` | **3.25:1** | 同样不合格 ⇒ **改字色也救不回来** |
| 白字 / `heat.1` | **1.81:1** | 不合格 |
| 白字 / `heat.0` | **1.34:1** | 不合格 |

`heat.2` 是「墨字与白字都不达标」的死区；加 2dp 白色描边托盘又会把色阶语义挡住，
把深浅色阶变成一样的白圈。因此**深色格上不放任何文字**，而不是「只在 heat.1 及更浅处放字」。
这三条不合格组合已写进门禁的反向断言（`HEAT_TEXT_IMPOSSIBLE`），
若哪天色阶被改亮到 4.5:1，门禁会失败并提示重新评估本条规则。

| 今天 | 2dp `accent` 描边圆角方框（套在色块上） | 图例「今天」 |
| 未来日期 | 无色块、数字 `inkTertiary` 38% 且不可点 | — |

**为什么「无记录」改虚线**（本项为评审发现的修正）：早期版本写「无填充，1dp `lineHairline` 方框」，
而 `lineHairline`/`canvas` 仅 **1.31:1**，被豁免为「装饰性不要求 3:1」。结果是低视力用户无法区分
「无记录」与「未来日期／空白」；同一语义在洞察页用的是虚线 `heatDash`（3.57:1），跨页两套线索、两个对比度。
现统一为 `heatDash` 虚线，与洞察页同一语义、同一线索、同一对比度。

**投入与完成是两个维度**必须落到视觉：日历上「有投入」用色块填充，「有完成」用右上角圆点，
两者叠加显示而不互相替代（规格 §6.2「未完成任务的时间同样计入投入」「仅勾选的事实计入完成数」）。

**空态插画的用法**：今天页与记录页的空态都是「插画在上、文案与按钮在下」，因此
**不在插画上加遮罩**（`scrimStops` 不施加）——文案落在 `canvas` 纯色上，加 0.86 遮罩只会把插画压暗。
插画按 `panel` 契约比例 656:320（= 328:160dp）满宽放置，不裁切、不留信箱空带。
空态区（月历或日期块 + 面板 + CTA）合计高于一屏，页面本身滚动；CTA 完整可见由
`verify_prototype_offline.py` 断言「空态主按钮完整落在可视区内」钉住。

**两处未达标的说明（不掩饰）**：

1. **日历格子 43.4×44dp**：受 7 列 × 360dp 屏宽的几何约束，单格上限 ≈44dp。若强行 48dp 则需横向滚动日历或减少列数。当前处置：格子间距 0、整个日历为一个手势容器（相邻格误触导向「最近格」而非错误日期）、并提供「日期选择器」二级入口（点月份标题打开系统风格日期选择列表，条目 ≥56dp）。**要求真机测误触率**（§8）。
2. **热力图格子 6.5dp**：完整的 53 周 × 7 天在 328dp 内物理上无法做到 48dp 目标（需 53×48 = 2544dp）。故格子**不**作为点按目标；交互改为区域手势 + TalkBack 语义索引 + 表格化明细替代。WCAG 2.2 SC 2.5.8（Target Size Minimum）允许「等效控件」例外，此处等效控件即**表格明细中的每一行（≥56dp）**。
